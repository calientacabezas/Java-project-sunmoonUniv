# 정확도 비교 실험: 규칙만 vs 하이브리드

## 1. 질문

LLM 추출과 의미 재정렬을 붙이면, 사람이 실제로 쓰는 표현(동의어·오타·외국어)에서 주인 물건을 더 잘 찾는가?

## 2. 비교 대상

| 방식 | 처리 과정 |
|---|---|
| 규칙만 (기준선) | `KeywordQueryParser`(enum 표준 이름만 인식, 동의어·외국어 없음) → 규칙 5개 점수 → 정렬 |
| 하이브리드 | `PiiMasker` → `LlmQueryParser` → 규칙 5개 점수 → 상위 10개 `LlmSemanticReRanker` (규칙 × 0.8 + 의미 × 0.2) |

두 방식은 **같은 습득물 30건과 같은 검색어 30개**를 씁니다. 하이브리드에서 LLM이 실패한 케이스는 기준선 파서로 대체되므로, 결과표에 실패 여부를 함께 적습니다.

## 3. 데이터

- 습득물: `data/sample/found_items.txt` 30건 (ITEM-001~030). 흰 이어폰 3개, 검정 지갑 2개처럼 비슷한 물건을 섞었습니다.
- 평가 케이스: `data/eval/eval_cases.txt` 30건, 각 케이스에 정답 습득물 ID.

| 유형 | 건수 | 예시 |
|---|---|---|
| NORMAL 표준 표현 | 10 | "공학관 3층에서 흰색 전자기기 갤럭시 버즈를 잃어버렸어요" |
| SYNONYM 동의어·약칭 | 10 | "공대 3층 강의실에 하얀 버즈 케이스", "곤색 후드티" |
| TYPO 오타 | 5 | "흰샥 갤럭시 벗즈 분실햇어요" |
| FOREIGN 외국어 | 5 | "I lost my white Galaxy Buds...", 중국어 1건 |

정답은 실험 전에 확정했습니다. 결과를 본 뒤 케이스를 바꾸지 않습니다.

## 4. 지표

- **주 지표: 상위 3개 포함률(Top-3)** = 정답이 상위 3개 안에 든 케이스 수 ÷ 30
- 보조 지표: 1위 적중률(Top-1), 평균 역순위(MRR)
- 유형별(NORMAL/SYNONYM/TYPO/FOREIGN)로 나눠서도 계산합니다.

## 5. 실행 방법

1. API 키를 환경변수 `LLM_API_KEY`로 설정합니다 (없으면 규칙만 결과만 나옵니다).
2. 이클립스: **Gradle Tasks → verification → evaluate** 더블클릭. 명령줄: `gradlew.bat evaluate`
3. 출력되는 "케이스별 정답 순위"와 마크다운 표를 아래 6장에 붙여 넣습니다.
4. LLM 응답은 매번 조금씩 다를 수 있으므로 **3회 실행해 평균**을 기록합니다.

### 오프라인 기준선 측정 (11/24, API 키 없음)

| 유형 | 건수 | 규칙만 Top-3 |
|---|---|---|
| NORMAL | 10 | 100.0% |
| SYNONYM | 10 | 90.0% |
| TYPO | 5 | 100.0% |
| FOREIGN | 5 | 0.0% |
| **전체** | 30 | 80.0% |

규칙만 Top-1 70.0%, MRR 0.768. 세부 특징 규칙이 원문 단어를 물품 이름과 비교하고 "모름" 항목을 분모에서 빼기 때문에, 동의어·오타 입력도 기준선이 상당 부분 맞힙니다. 차이는 외국어 입력에서 가장 크게 날 것으로 예상합니다.

## 7. 해석할 때 주의

- NORMAL에서는 차이가 작고 SYNONYM·FOREIGN에서 커지는 것이 예상 결과입니다. 그렇지 않으면 원인을 적습니다.
- 하이브리드가 오히려 틀린 케이스는 빼지 말고 사례로 분석합니다. 발표에서 신뢰도를 높여 줍니다.
- 30건은 작은 표본이므로 "통계적으로 유의하다"는 표현은 쓰지 않습니다.
